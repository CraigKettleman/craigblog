## Motivation: From Chatbots to Autonomous Agents

Modern LLMs are increasingly deployed not just as conversational assistants but as autonomous agents that interact with external tools, APIs, databases, and environments over multiple steps. This shift—from single-turn chatbots to multi-step agents—introduces fundamentally new RL challenges that require rethinking how we train, evaluate, and deploy language models.

<figure id="ch12.f1"><figcaption><span class="hh-tag">Figure 12.1:</span>From Chatbots to Autonomous Agents: Traditional LLM chatbots operate in a single-step conversational loop with immediate human feedback. Autonomous agents plan across multiple tool interactions, receive feedback from real-world execution environments, and optimize for sparse terminal rewards (task success/failure).</figcaption></figure>

The key differences that demand new RL approaches:

<ul><li>Multi-step reasoning: Agents must plan across 10–100+ tool calls, not just generate a single response.</li><li>External environment feedback: Rewards come from real-world execution (test suites pass, web pages load, code compiles) — not just human preference scores.</li><li>Structured actions: Actions are not just tokens but structured outputs (JSON tool calls, API payloads, code blocks).</li><li>Long horizons with sparse rewards: Success/failure may only be determined after many intermediate steps.</li></ul>

## Trajectory Buffers for LLM Agents

In the context of LLM agents, traditional RL replay buffers undergo a structural transformation. Instead of storing low-dimensional numerical tensors, agentic buffers — often called Trajectory Buffers, Experience Pools, or Memory Banks — manage complex textual histories, tool execution outputs, and explicit reasoning steps.

### Mathematical Structure of an LLM Agent Buffer

In classic RL, a replay buffer stores a flat tuple <math alttext="(s,a,r,s^{\prime})" display="inline"><semantics><mrow><mo stretchy="false">(</mo><mi>s</mi><mo>,</mo><mi>a</mi><mo>,</mo><mi>r</mi><mo>,</mo><msup><mi>s</mi><mo>′</mo></msup><mo stretchy="false">)</mo></mrow></semantics></math>. For an LLM agent, this expands into high-dimensional tokenized text structures:

<div class="hh-equation" id="ch12.e1"><math alttext="\boxed{e_{t}=\left(\mathcal{S}_{t},\;\mathcal{A}_{t},\;\mathcal{R}_{t},\;\mathcal{S}_{t+1}\right)}" display="block"><semantics><menclose notation="box"><mrow><msub><mi>e</mi><mi>t</mi></msub><mo>=</mo><mrow><mo>(</mo><msub><mi>𝒮</mi><mi>t</mi></msub><mo>,</mo><msub><mi>𝒜</mi><mi>t</mi></msub><mo>,</mo><msub><mi>ℛ</mi><mi>t</mi></msub><mo>,</mo><msub><mi>𝒮</mi><mrow><mi>t</mi><mo>+</mo><mn>1</mn></mrow></msub><mo>)</mo></mrow></mrow></menclose></semantics></math><span class="hh-equation-number">(12.1)</span></div>

<ul><li><math alttext="\mathcal{S}_{t}" display="inline"><semantics><msub><mi>𝒮</mi><mi>t</mi></msub></semantics></math>: The complete context state — system prompt, user objective, conversation history, and current environmental variables (e.g., HTML source code, directory structures, database schemas).</li><li><math alttext="\mathcal{A}_{t}" display="inline"><semantics><msub><mi>𝒜</mi><mi>t</mi></msub></semantics></math>: The agent’s generated output, typically composed of a Chain-of-Thought (CoT) reasoning string followed by a structured tool call:<math alttext="\mathcal{A}_{t}=\{\text{text}_{\text{reasoning}},\;\text{json}_{\text{tool\_call}}\}" display="block"><semantics><mrow><msub><mi>𝒜</mi><mi>t</mi></msub><mo>=</mo><mrow><mo stretchy="false">{</mo><msub><mtext>text</mtext><mtext>reasoning</mtext></msub><mo rspace="0.447em">,</mo><msub><mtext>json</mtext><mtext>tool_call</mtext></msub><mo stretchy="false">}</mo></mrow></mrow></semantics></math><span class="hh-tag">(12.2)</span></li><li><math alttext="\mathcal{R}_{t}" display="inline"><semantics><msub><mi>ℛ</mi><mi>t</mi></msub></semantics></math>: Evaluation signals derived from external execution environments (unit test passes, compiler flags, API response codes) or verified by an LLM-as-a-judge system.</li><li><math alttext="\mathcal{S}_{t+1}" display="inline"><semantics><msub><mi>𝒮</mi><mrow><mi>t</mi><mo>+</mo><mn>1</mn></mrow></msub></semantics></math>: The updated context window, which appends tool output text or error logs directly into the conversation history.</li></ul>

## Operational Paradigms

LLM agents leverage specialized trajectory buffers through three primary optimization methodologies:

### A. Self-Correction and Thought Refinement

Two representative methods in this category are STaR [419] and Reflexion [326]. When an agent fails a multi-step execution trace, the sub-optimal sequence is saved to the buffer. The framework later samples this trajectory and prompts the LLM to generate an explicit textual critique of its past performance:

<div class="hh-equation" id="ch12.e3"><math alttext="\text{Critique}\leftarrow\text{LLM}(\mathcal{S}_{\text{failed}},\;\mathcal{A}_{\text{failed}},\;\mathcal{R}_{=0})" display="block"><semantics><mrow><mtext>Critique</mtext><mo stretchy="false">←</mo><mrow><mtext>LLM</mtext><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><msub><mi>𝒮</mi><mtext>failed</mtext></msub><mo>,</mo><msub><mi>𝒜</mi><mtext>failed</mtext></msub><mo>,</mo><msub><mi>ℛ</mi><mrow><mphantom></mphantom><mo>=</mo><mn>0</mn></mrow></msub><mo stretchy="false">)</mo></mrow></mrow></mrow></semantics></math><span class="hh-equation-number">(12.3)</span></div>

Once a corrected trajectory achieves a positive reward, it is moved to an optimal experience pool used to update the network weights via fine-tuning (SFT on successful trajectories) or RL (GRPO [323] with binary pass/fail rewards).

### B. Off-Policy Exploration

This paradigm, exemplified by ReAct [409] and related tool-use frameworks, involves extensive autonomous exploration. During autonomous exploration (web navigation, database querying, code generation), agents log thousands of exploratory execution paths. The trajectory buffer acts as a filter:

<ul><li>Success filtering: Only trajectories achieving the goal are kept for training.</li><li>Efficiency ranking: Among successful traces, prefer the shortest/most efficient tool-use paths.</li><li>Diversity sampling: Maintain a diverse set of solution strategies to prevent mode collapse.</li></ul>

The optimization algorithm (typically GRPO [323] or filtered SFT) computes losses exclusively over efficient, successful trajectories while discarding meandering runs.

### C. Non-Parametric In-Context Learning (RAG over Experiences)

Instead of modifying neural network weights, the trajectory buffer can function as a vector database. Given a new user goal <math alttext="\mathcal{G}_{\text{new}}" display="inline"><semantics><msub><mi>𝒢</mi><mtext>new</mtext></msub></semantics></math>, the system retrieves the most relevant past experiences:

<div class="hh-equation" id="ch12.e4"><math alttext="\boxed{\mathcal{E}_{\text{retrieved}}=\arg\max_{e\in\mathcal{B}}\text{sim}\!\left(\text{Embed}(\mathcal{G}_{\text{new}}),\;\text{Embed}(e)\right)}" display="block"><semantics><menclose notation="box"><mrow><msub><mi>ℰ</mi><mtext>retrieved</mtext></msub><mo>=</mo><mrow><mrow><mi>arg</mi><mo lspace="0.167em">⁡</mo><munder><mi>max</mi><mrow><mi>e</mi><mo>∈</mo><mi>ℬ</mi></mrow></munder></mrow><mo lspace="0.167em" rspace="0em">​</mo><mpadded width="1.521em"><mtext>sim</mtext></mpadded><mo lspace="0em" rspace="0em">​</mo><mrow><mo>(</mo><mrow><mtext>Embed</mtext><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><msub><mi>𝒢</mi><mtext>new</mtext></msub><mo stretchy="false">)</mo></mrow></mrow><mo>,</mo><mrow><mtext>Embed</mtext><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><mi>e</mi><mo stretchy="false">)</mo></mrow></mrow><mo>)</mo></mrow></mrow></mrow></menclose></semantics></math><span class="hh-equation-number">(12.4)</span></div>

The top-<math alttext="k" display="inline"><semantics><mi>k</mi></semantics></math> similar successful historical runs are injected directly into the prompt context as few-shot demonstrations. This approach:

<ul><li>Requires zero training — pure retrieval-augmented generation</li><li>Adapts instantly to new tasks if similar experiences exist in the buffer</li><li>Scales with buffer size (more experiences = better coverage)</li><li>Complements parametric learning (use retrieval for rare cases, weights for common patterns)</li></ul>

### STaR: Self-Taught Reasoner (Detailed)

STaR [419] is an iterative self-improvement method that bootstraps reasoning capabilities without external reward models. The core insight: if the model can occasionally solve a problem correctly, it can learn from its own successes.

Algorithm:

<ol><li>Generate: For each problem <math alttext="x_{i}" display="inline"><semantics><msub><mi>x</mi><mi>i</mi></msub></semantics></math> in dataset <math alttext="\mathcal{D}" display="inline"><semantics><mi>𝒟</mi></semantics></math>, sample a reasoning trace <math alttext="z_{i}\sim\pi_{\theta}(\cdot|x_{i})" display="inline"><semantics><mrow><msub><mi>z</mi><mi>i</mi></msub><mo>∼</mo><msub><mi>π</mi><mi>θ</mi></msub><mrow><mo stretchy="false">(</mo><mo lspace="0em" rspace="0em">⋅</mo><mo fence="false" rspace="0.167em" stretchy="false">|</mo><msub><mi>x</mi><mi>i</mi></msub><mo stretchy="false">)</mo></mrow></mrow></semantics></math> followed by an answer <math alttext="\hat{y}_{i}" display="inline"><semantics><msub><mover accent="true"><mi>y</mi><mo>^</mo></mover><mi>i</mi></msub></semantics></math>.</li><li>Filter: Keep only traces where <math alttext="\hat{y}_{i}=y_{i}^{*}" display="inline"><semantics><mrow><msub><mover accent="true"><mi>y</mi><mo>^</mo></mover><mi>i</mi></msub><mo>=</mo><msubsup><mi>y</mi><mi>i</mi><mo>∗</mo></msubsup></mrow></semantics></math> (correct answer). Define success set <math alttext="\mathcal{D}_{\text{pass}}=\{(x_{i},z_{i},y_{i}^{*}):\hat{y}_{i}=y_{i}^{*}\}" display="inline"><semantics><mrow><msub><mi>𝒟</mi><mtext>pass</mtext></msub><mo>=</mo><mrow><mo stretchy="false">{</mo><mrow><mo stretchy="false">(</mo><msub><mi>x</mi><mi>i</mi></msub><mo>,</mo><msub><mi>z</mi><mi>i</mi></msub><mo>,</mo><msubsup><mi>y</mi><mi>i</mi><mo>∗</mo></msubsup><mo rspace="0.278em" stretchy="false">)</mo></mrow><mo rspace="0.278em">:</mo><mrow><msub><mover accent="true"><mi>y</mi><mo>^</mo></mover><mi>i</mi></msub><mo>=</mo><msubsup><mi>y</mi><mi>i</mi><mo>∗</mo></msubsup></mrow><mo stretchy="false">}</mo></mrow></mrow></semantics></math>.</li><li>Rationalization (key innovation): For problems where the model failed, generate a “rationalization” — a trace conditioned on the correct answer: <math alttext="z_{i}^{\text{rat}}\sim\pi_{\theta}(\cdot|x_{i},y_{i}^{*})" display="inline"><semantics><mrow><msubsup><mi>z</mi><mi>i</mi><mtext>rat</mtext></msubsup><mo>∼</mo><msub><mi>π</mi><mi>θ</mi></msub><mrow><mo stretchy="false">(</mo><mo lspace="0em" rspace="0em">⋅</mo><mo fence="false" rspace="0.167em" stretchy="false">|</mo><msub><mi>x</mi><mi>i</mi></msub><mo>,</mo><msubsup><mi>y</mi><mi>i</mi><mo>∗</mo></msubsup><mo stretchy="false">)</mo></mrow></mrow></semantics></math>. This teaches the model to reason <em>backward</em> from solutions.</li><li>Fine-tune: Update <math alttext="\theta" display="inline"><semantics><mi>θ</mi></semantics></math> via SFT on <math alttext="\mathcal{D}_{\text{pass}}\cup\mathcal{D}_{\text{rationalized}}" display="inline"><semantics><mrow><msub><mi>𝒟</mi><mtext>pass</mtext></msub><mo>∪</mo><msub><mi>𝒟</mi><mtext>rationalized</mtext></msub></mrow></semantics></math>.</li><li>Iterate: Repeat from step 1 with the improved model.</li></ol>

### Reflexion: Verbal Reinforcement Learning (Detailed)

Reflexion [326] introduces a radical paradigm: RL without weight updates. Instead of gradient-based learning, the agent improves through natural-language self-critique stored in an episodic memory.

### ReAct: Reasoning + Acting (Detailed)

ReAct [409] establishes the dominant prompting paradigm for tool-using agents by interleaving explicit reasoning steps with environment actions in a single generation stream.

Generation format:

Formal definition: A ReAct trajectory is <math alttext="\tau=(t_{1},a_{1},o_{1},t_{2},a_{2},o_{2},\ldots)" display="inline"><semantics><mrow><mi>τ</mi><mo>=</mo><mrow><mo stretchy="false">(</mo><msub><mi>t</mi><mn>1</mn></msub><mo>,</mo><msub><mi>a</mi><mn>1</mn></msub><mo>,</mo><msub><mi>o</mi><mn>1</mn></msub><mo>,</mo><msub><mi>t</mi><mn>2</mn></msub><mo>,</mo><msub><mi>a</mi><mn>2</mn></msub><mo>,</mo><msub><mi>o</mi><mn>2</mn></msub><mo>,</mo><mi mathvariant="normal">…</mi><mo stretchy="false">)</mo></mrow></mrow></semantics></math> where:

<ul><li><math alttext="t_{i}" display="inline"><semantics><msub><mi>t</mi><mi>i</mi></msub></semantics></math>: Thought (internal reasoning, not executed)</li><li><math alttext="a_{i}" display="inline"><semantics><msub><mi>a</mi><mi>i</mi></msub></semantics></math>: Action (tool call, executed in environment)</li><li><math alttext="o_{i}" display="inline"><semantics><msub><mi>o</mi><mi>i</mi></msub></semantics></math>: Observation (environment response, appended to context)</li></ul>

Why it works: Thoughts create an “inner monologue” that helps the model plan before acting, reducing impulsive tool calls. The explicit reasoning trace also makes the agent’s decision process auditable and debuggable.

Training ReAct agents with RL:

<ul><li>Action-level rewards: Only actions receive reward signals (thoughts are auxiliary).</li><li>Thought quality: Implicitly optimized — better thoughts <math alttext="\rightarrow" display="inline"><semantics><mo stretchy="false">→</mo></semantics></math> better actions <math alttext="\rightarrow" display="inline"><semantics><mo stretchy="false">→</mo></semantics></math> higher rewards.</li><li>Format enforcement: Include format penalties in the reward for malformed actions (missing JSON, hallucinated tools).</li><li>RL objective: <math alttext="r(\tau)=r_{\text{task}}-\lambda_{\text{format}}\cdot\text{format\_violations}-\lambda_{\text{length}}\cdot\text{num\_steps}" display="inline"><semantics><mrow><mrow><mi>r</mi><mo>⁡</mo><mrow><mo stretchy="false">(</mo><mi>τ</mi><mo stretchy="false">)</mo></mrow></mrow><mo>=</mo><mrow><msub><mi>r</mi><mtext>task</mtext></msub><mo>−</mo><mrow><msub><mi>λ</mi><mtext>format</mtext></msub><mo lspace="0.222em" rspace="0.222em">⋅</mo><mtext>format_violations</mtext></mrow><mo>−</mo><mrow><msub><mi>λ</mi><mtext>length</mtext></msub><mo lspace="0.222em" rspace="0.222em">⋅</mo><mtext>num_steps</mtext></mrow></mrow></mrow></semantics></math></li></ul>

### LATS: Language Agent Tree Search (Detailed)

Algorithm (adapted for LLM agents):

### AgentQ: DPO on Agent Trajectories (Detailed)

AgentQ [294] bridges offline preference learning (DPO) with online agent execution by automatically generating preference pairs from trajectory outcomes.

Pipeline:

<ol><li>Rollout: Execute <math alttext="N" display="inline"><semantics><mi>N</mi></semantics></math> trajectories per task using the current policy <math alttext="\pi_{\theta}" display="inline"><semantics><msub><mi>π</mi><mi>θ</mi></msub></semantics></math>.</li><li>Evaluate: Score each trajectory with execution-based reward (binary pass/fail or scalar metric).</li><li>Pair construction: For each task, construct preference pairs:<math alttext="(\tau_{w},\tau_{l})\text{ where }r(\tau_{w})&gt;r(\tau_{l})" display="block"><semantics><mrow><mrow><mrow><mo stretchy="false">(</mo><msub><mi>τ</mi><mi>w</mi></msub><mo>,</mo><msub><mi>τ</mi><mi>l</mi></msub><mo stretchy="false">)</mo></mrow><mo lspace="0em" rspace="0em">​</mo><mtext> where </mtext><mo lspace="0em" rspace="0em">​</mo><mi>r</mi><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><msub><mi>τ</mi><mi>w</mi></msub><mo stretchy="false">)</mo></mrow></mrow><mo>&gt;</mo><mrow><mi>r</mi><mo>⁡</mo><mrow><mo stretchy="false">(</mo><msub><mi>τ</mi><mi>l</mi></msub><mo stretchy="false">)</mo></mrow></mrow></mrow></semantics></math><span class="hh-tag">(12.9)</span>Among trajectories for the same task, the one with highest reward = chosen; lowest = rejected.</li><li>DPO update: Apply standard DPO loss over trajectory-level log-probabilities:<math alttext="\mathcal{L}_{\text{AgentQ}}=-\log\sigma\!\left(\beta\left[\log\frac{\pi_{\theta}(\tau_{w})}{\pi_{\text{ref}}(\tau_{w})}-\log\frac{\pi_{\theta}(\tau_{l})}{\pi_{\text{ref}}(\tau_{l})}\right]\right)" display="block"><semantics><mrow><msub><mi>ℒ</mi><mtext>AgentQ</mtext></msub><mo>=</mo><mrow><mo rspace="0.167em">−</mo><mrow><mi>log</mi><mo lspace="0.167em">⁡</mo><mrow><mpadded width="0.437em"><mi>σ</mi></mpadded><mo>⁡</mo><mrow><mo>(</mo><mrow><mi>β</mi><mo>⁡</mo><mrow><mo>[</mo><mrow><mrow><mi>log</mi><mo lspace="0.167em">⁡</mo><mfrac><mrow><msub><mi>π</mi><mi>θ</mi></msub><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><msub><mi>τ</mi><mi>w</mi></msub><mo stretchy="false">)</mo></mrow></mrow><mrow><msub><mi>π</mi><mtext>ref</mtext></msub><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><msub><mi>τ</mi><mi>w</mi></msub><mo stretchy="false">)</mo></mrow></mrow></mfrac></mrow><mo>−</mo><mrow><mi>log</mi><mo lspace="0.167em">⁡</mo><mfrac><mrow><msub><mi>π</mi><mi>θ</mi></msub><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><msub><mi>τ</mi><mi>l</mi></msub><mo stretchy="false">)</mo></mrow></mrow><mrow><msub><mi>π</mi><mtext>ref</mtext></msub><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><msub><mi>τ</mi><mi>l</mi></msub><mo stretchy="false">)</mo></mrow></mrow></mfrac></mrow></mrow><mo>]</mo></mrow></mrow><mo>)</mo></mrow></mrow></mrow></mrow></mrow></semantics></math><span class="hh-tag">(12.10)</span></li><li>Iterate: Updated <math alttext="\pi_{\theta}" display="inline"><semantics><msub><mi>π</mi><mi>θ</mi></msub></semantics></math> generates new (better) trajectories in the next round.</li></ol>

Key design choices:

<ul><li>MCTS-guided exploration: Use LATS during rollout phase to generate diverse, high-quality trajectories (better training data).</li><li>Step-level DPO: Instead of comparing full trajectories, compare at the <em>action level</em> — given the same prefix, which next action leads to success?</li><li>Self-play improvement: Each DPO iteration produces a better policy that generates better trajectories that produce better training pairs — a virtuous cycle.</li></ul>

Results: On WebShop, AgentQ achieves absolute 50% <math alttext="\rightarrow" display="inline"><semantics><mo stretchy="false">→</mo></semantics></math> 82% success rate improvement over the base policy in 3 DPO iterations.

### Voyager: Lifelong Learning via Skill Libraries (Detailed)

Voyager [362] introduces compositional skill accumulation — the agent builds a growing library of reusable code functions that serve as high-level actions.

Architecture:

<ol><li>Automatic Curriculum: An LLM proposes progressively harder tasks based on the agent’s current skill inventory: “You can now mine wood and craft planks. Next challenge: build a crafting table.”</li><li>Skill Generation: For each task, the agent writes a JavaScript function (executable code) that solves it:<math alttext="\text{skill}_{i}=\text{LLM}(\text{task}_{i},\text{environment\_docs},\text{error\_feedback})" display="block"><semantics><mrow><msub><mtext>skill</mtext><mi>i</mi></msub><mo>=</mo><mrow><mtext>LLM</mtext><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><msub><mtext>task</mtext><mi>i</mi></msub><mo>,</mo><mtext>environment_docs</mtext><mo>,</mo><mtext>error_feedback</mtext><mo stretchy="false">)</mo></mrow></mrow></mrow></semantics></math><span class="hh-tag">(12.11)</span></li><li>Verification: Execute the code in the environment. If it succeeds, add to the skill library. If not, iterate with error feedback (up to 5 retries).</li><li>Skill Library (vector DB): Each verified skill stored with:<span class="hh-tag">•</span>Function signature + docstring (for retrieval)<span class="hh-tag">•</span>Embedding of the task description (for semantic search)<span class="hh-tag">•</span>Dependencies (which other skills it calls)</li><li>Retrieval + Composition: For new tasks, retrieve the top-<math alttext="k" display="inline"><semantics><mi>k</mi></semantics></math> most relevant skills and compose them:<math alttext="\text{solution}=\text{LLM}(\text{new\_task},\text{retrieve}(\text{skill\_library},k{=}5))" display="block"><semantics><mrow><mtext>solution</mtext><mo>=</mo><mrow><mtext>LLM</mtext><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><mtext>new_task</mtext><mo>,</mo><mrow><mtext>retrieve</mtext><mo lspace="0em" rspace="0em">​</mo><mrow><mo stretchy="false">(</mo><mtext>skill_library</mtext><mo>,</mo><mrow><mi>k</mi><mo>=</mo><mn>5</mn></mrow><mo stretchy="false">)</mo></mrow></mrow><mo stretchy="false">)</mo></mrow></mrow></mrow></semantics></math><span class="hh-tag">(12.12)</span></li></ol>

Key insight: Skills are compositional — complex behaviors emerge from combining simple verified functions. The agent never forgets (library is persistent) and improves monotonically (only verified skills are added).

### RLEF: RL from Execution Feedback (Detailed)

RLEF [201] applies online RL with deterministic execution-based rewards to code generation agents, establishing the simplest effective paradigm for agentic training.

Training loop:

<ol><li>Sample task: Draw a coding problem with test cases <math alttext="(x,\text{tests})" display="inline"><semantics><mrow><mo stretchy="false">(</mo><mi>x</mi><mo>,</mo><mtext>tests</mtext><mo stretchy="false">)</mo></mrow></semantics></math> from the training set.</li><li>Generate: The agent produces a solution trajectory (reading files, writing code, running tests) using the current policy <math alttext="\pi_{\theta}" display="inline"><semantics><msub><mi>π</mi><mi>θ</mi></msub></semantics></math>.</li><li>Execute: Run the test suite in a sandboxed environment. Reward:<math alttext="r=\frac{\text{\# tests passed}}{\text{\# total tests}}\in[0,1]" display="block"><semantics><mrow><mi>r</mi><mo>=</mo><mfrac><mtext># tests passed</mtext><mtext># total tests</mtext></mfrac><mo>∈</mo><mrow><mo stretchy="false">[</mo><mrow><mn>0</mn><mo>,</mo><mn>1</mn></mrow><mo stretchy="false">]</mo></mrow></mrow></semantics></math><span class="hh-tag">(12.13)</span></li><li>Update: Apply GRPO/PPO using <math alttext="r" display="inline"><semantics><mi>r</mi></semantics></math> as the reward signal.</li><li>Repeat: Thousands of iterations with fresh tasks.</li></ol>

Why execution feedback is ideal for RL:

<ul><li>Zero noise: Unlike human preferences, test results are deterministic. Same code <math alttext="\rightarrow" display="inline"><semantics><mo stretchy="false">→</mo></semantics></math> same reward every time. This eliminates reward noise that destabilizes RL training.</li><li>Infinite scale: Can generate unlimited tasks programmatically (random algorithms, API integration tests, data transformations).</li><li>No reward hacking: Unlike learned reward models, a test suite can’t be “fooled” (assuming tests are well-written). The agent must actually solve the problem.</li><li>Dense signal: Partial test passage (<math alttext="r=0.6" display="inline"><semantics><mrow><mi>r</mi><mo>=</mo><mn>0.6</mn></mrow></semantics></math>) provides richer gradient than binary pass/fail.</li></ul>

## State-of-the-Art RL for LLM Agents

RL techniques for LLM agents focus on on-policy policy gradients combined with fine-grained credit assignment. Because agents execute complex multi-turn trajectories involving tool interactions, API queries, and code execution, standard single-turn alignment algorithms must be heavily modified.

### PPO for Interactive Agents

PPO[319] remains valuable for agents operating in highly stochastic environments where step-level value estimation helps. The critic provides per-step advantage signals, enabling finer credit assignment when tool outputs are unpredictable:

<ul><li>Step-level advantage estimation via GAE handles variable-length tool outputs</li><li>Value head learns to predict “how likely is this trajectory to succeed from here”</li><li>More stable when external tools return catastrophic errors that spike reward variance</li><li>Trade-off: requires <math alttext="2\times" display="inline"><semantics><mrow><mn>2</mn><mo lspace="0.222em">×</mo></mrow></semantics></math> memory (critic) but provides denser learning signals</li></ul>

### Alternative Paradigms

<ul><li>Iterative STaR (Self-Taught Reasoner)[419]: Rather than continuous RL, use iterative offline loops. Generate trajectories <math alttext="\rightarrow" display="inline"><semantics><mo stretchy="false">→</mo></semantics></math> filter failures <math alttext="\rightarrow" display="inline"><semantics><mo stretchy="false">→</mo></semantics></math> SFT on successes <math alttext="\rightarrow" display="inline"><semantics><mo stretchy="false">→</mo></semantics></math> repeat. ## Interactive RL Environments for Agent Training

The dominant paradigm in early agentic RL relied on static datasets: curated trajectories, offline preference pairs, or fixed benchmark suites. While tractable, this approach has a fundamental limitation—agents trained on static data cannot discover novel strategies through environment interaction, and reward signals are limited to what was anticipated at dataset creation time. The field has shifted decisively toward interactive RL environments: live simulators where agents execute actions, receive feedback, and update policies based on real outcomes.

### NeMo Gym (NVIDIA)

NeMo Gym[271] is NVIDIA’s framework for interactive RL environments designed specifically for LLM agent training. Its architecture cleanly separates the agent (the LLM policy) from the environment (the task simulator), enabling independent scaling of each component.

Key design principles:

<ul><li>Multi-turn rollouts: Environments support extended interaction sequences, not just single-step queries. The agent can call tools, receive results, and continue reasoning across many turns.</li><li>Tool-calling verification: Rewards are computed by executing the agent’s tool calls and verifying outcomes against ground truth—providing dense, reliable signal.</li><li>Decoupled agent/environment: The environment runs as a separate service, allowing heterogeneous compute allocation (e.g., GPU for the agent, CPU for environment simulation).</li></ul>

Nemotron 3 Super was trained using NeMo Gym with 21 environment configurations spanning math, code, tool use, and multi-turn dialogue, generating 1.2M rollouts. The diversity of environments is critical: agents trained on a single environment type tend to overfit its reward structure.

### RLFactory

RLFactory[369] is a plug-and-play framework for multi-round tool-use RL, designed to minimize the engineering overhead of connecting LLM policies to diverse tool environments.

### MOSAIC: Safety in Agentic Training

As agentic RL environments become more capable, safety becomes a first-class concern. MOSAIC[50] (March 2026) addresses the problem of training agents that are both capable and safe in interactive environments.

The core MOSAIC framework introduces a plan <math alttext="\rightarrow" display="inline"><semantics><mo stretchy="false">→</mo></semantics></math> check <math alttext="\rightarrow" display="inline"><semantics><mo stretchy="false">→</mo></semantics></math> act or refuse loop:

<ol><li>Plan: The agent generates a candidate action sequence.</li><li>Check: A safety verifier evaluates the plan against a constraint set (harm categories, policy rules).</li><li>Act or Refuse: If the plan passes, execute; otherwise, generate a refusal with explanation.</li></ol>

Safety is trained via trajectory-level preference learning: rather than labeling individual actions as safe/unsafe, MOSAIC labels entire trajectories, capturing the cumulative safety impact of multi-step plans. This is critical because individual actions that appear benign can compose into harmful sequences.

xAI’s Grok 4.5 (July 2026) [389] introduced a novel data source: anonymized developer-session traces from Cursor—the actual keystrokes, navigation patterns, and editing sequences of engineers working in real codebases. Mid-trained on these traces, Grok 4.5 achieved top rankings on agentic tool-use benchmarks. This signals a “compute + traces” paradigm: once compute is scaled, the scarce input becomes <em>recordings of target behavior</em>—analogous to how AlphaGo was bootstrapped from human games before transitioning to self-play. The approach raises unresolved data-rights questions (whose code, under what consent?) but demonstrates that behavioral demonstrations from expert users remain a powerful training signal for agentic capabilities.
